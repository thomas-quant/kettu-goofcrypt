# Testing Patterns

**Analysis Date:** 2026-05-30

## Test Framework

**Runner:**
- No standard test framework (no Jest, Vitest, Mocha, etc.)
- Custom hand-rolled harness: `tests/harness.ts`
- Test runner entry: `scripts/test.mjs` — esbuild-bundles the harness (including the `.wasm` asset) then executes under Node with `--experimental-wasm-stringref`

**Assertion Library:**
- None — assertions are inline boolean evaluations using a custom `check(name, cond, detail)` helper defined in the harness itself

**Run Commands:**
```bash
npm test                  # Build harness bundle then run under Node
node --experimental-wasm-stringref scripts/test.mjs   # Same, explicit
```

## Test File Organization

**Location:**
- Separate `tests/` directory at project root, not co-located with source
- Single test file: `tests/harness.ts`
- Built output lands in `tests/dist/harness.mjs` (gitignored; generated by `scripts/test.mjs`)

**Naming:**
- One harness file; no naming convention needed beyond `harness.ts`

**Structure:**
```
tests/
└── harness.ts          # Cross-compat + identity test harness (131 lines)
    dist/               # Generated by npm test; not committed
    └── harness.mjs
scripts/
└── test.mjs            # Build + run driver for the harness
```

## Test Structure

**Suite Organization:**
The harness uses numbered console-printed sections, not `describe` blocks:

```typescript
console.log("\n[1] Cross-compat: ours.hide → theirs.reveal");
for (const c of CASES) {
    try {
        const stego = ourHide(c.msg, c.pw, CHANNEL, c.cover, rng);
        const back = sc.reveal(stego, c.pw, CHANNEL);
        check(c.name, back === c.msg, `got ${JSON.stringify(back.slice(0, 40))}`);
    } catch (e) {
        check(c.name, false, "threw " + (e as Error).message);
    }
}
```

**`check` helper:**
```typescript
let passed = 0;
let failed = 0;
function check(name: string, cond: boolean, detail = "") {
    if (cond) {
        passed++;
        console.log(`  ✓ ${name}`);
    } else {
        failed++;
        console.error(`  ✗ ${name}${detail ? "  — " + detail : ""}`);
    }
}
```

**Exit behavior:**
```typescript
process.exit(failed === 0 ? 0 : 1);
```
Non-zero exit on any failure, which makes `npm test` fail in CI.

**Patterns:**
- Test cases defined as a typed `Case[]` array (`CASES` constant) — data-driven
- Each section loops over the same `CASES` array
- One-off checks (wrong-password, salt-sensitivity, random round-trip) use anonymous blocks `{ ... }`
- No setup/teardown — state is freshly initialized at the top of the file

## Mocking

**Framework:** None

**Patterns:**
The harness does not mock any modules. Instead it uses real implementations throughout:
- The REAL `stegcloak-rs` WASM library is imported and run as the reference
- `webcrypto.getRandomValues` from `node:crypto` is used as the test RNG (passed as the `rng` parameter to `ourHide`)
- No dependency injection stubs or spies

```typescript
import { webcrypto } from "node:crypto";
const rng = (n: number) => {
    const b = new Uint8Array(n);
    webcrypto.getRandomValues(b);
    return b;
};
const sc = new StegCloak(); // real WASM reference implementation
```

**Why no mocking:**
The harness is a byte-compatibility gate — the entire point is running the real WASM reference and verifying the pure-JS implementation produces identical output. Mocking would defeat this.

**What to Mock (if adding new tests):**
- `vendetta` global (not present in Node) would need to be mocked for any tests touching `src/discord/`, `src/ui/`, or `src/index.ts`
- `getRandomBytes` from `src/crypto/random.ts` can accept a deterministic RNG via the `rng` parameter in `hide`/`encryptWithKey` — use that instead of mocking

**What NOT to Mock:**
- The `stegcloak-rs` WASM reference — the cross-compat check is the harness's primary value
- `@noble/hashes` or `@noble/ciphers` — these are the crypto primitives being tested for correctness

**Test Data:**
```typescript
interface Case {
    name: string;
    msg: string;
    pw: string;
    cover: string;
}

const CASES: Case[] = [
    { name: "ascii, single-space cover", msg: "hello world", pw: "p1", cover: "Sending a normal message" },
    { name: "no-whitespace cover (S=0)", msg: "no whitespace cover", pw: "k", cover: "abcdefghij" },

    { name: "tabs + multi-space runs", msg: "tabs and spaces", pw: "k", cover: "a\tb  c\n\nd   e" },
    { name: "NBSP + unicode whitespace", msg: "weird ws", pw: "pw", cover: "a b c　d" },
    { name: "leading/trailing whitespace", msg: "edges", pw: "pw", cover: "   padded   " },
    { name: "unicode message + emoji", msg: "unicode 😀 café — naïve", pw: "k", cover: "Hello there my friend" },

```

**Location:**
- All test fixtures are inlined in `tests/harness.ts` — no separate fixture files

**Random fixture generation:**
- Section [4] uses `rng` to generate 2000 random `Uint8Array` buffers of random length (1–256 bytes) to test `conceal`/`extract` round-trip identity

## Coverage

**Requirements:** None enforced (no coverage tooling configured)

**View Coverage:**
No coverage command. The harness is run as a pass/fail binary gate.

## Test Types

**Unit Tests:**
- None in the traditional sense
- `src/selfTest.ts` is an on-load unit check that runs on-device in Hermes; exercises `parsePasswords`, `conceal`/`extract`/`isCloaked`, `toBase64`/`fromBase64`, `passwordId`
  - Location: `src/selfTest.ts`
  - Invoked by: `src/index.ts` `onLoad`
  - Returns `null` on success or a short failure description string

**Integration / Cross-compatibility Tests:**
- `tests/harness.ts` — the primary test suite
- Sections 1 and 2 are bidirectional interop checks against the real `stegcloak-rs` WASM library
- Sections 3–6 test internal identity, isCloaked parity, error behavior, and salt sensitivity

**E2E Tests:**
- Not used; the Discord/Vendetta runtime cannot be automated

## Common Patterns

**Data-driven section loop:**
```typescript
console.log("\n[2] Cross-compat: theirs.hide → ours.reveal");
for (const c of CASES) {
    try {
        const stego = sc.hide(c.msg, c.pw, CHANNEL, c.cover);
        const back = ourReveal(stego, c.pw, CHANNEL);
        check(c.name, back === c.msg, `got ${JSON.stringify(back.slice(0, 40))}`);
    } catch (e) {
        check(c.name, false, "threw " + (e as Error).message);
    }
}
```

**Error class testing:**
```typescript
let threw = false;
try {
    ourReveal(stego, "wrongpass", CHANNEL);
} catch (e) {
    threw = e instanceof DecryptionError;
}
check("ours.reveal wrong password → DecryptionError", threw);
```

**Random buffer identity check:**
```typescript
for (let i = 0; i < 2000; i++) {
    const buf = rng(((Math.random() * 256) | 0) + 1);
    if (Buffer.compare(Buffer.from(buf), Buffer.from(extract(conceal(buf)))) !== 0) {
        ok = false;
        badLen = buf.length;
        break;
    }
}
check("conceal/extract identity (2000 random buffers)", ok, ok ? "" : `mismatch at len=${badLen}`);
```

**On-device self-test pattern (selfTest returns null or description):**
```typescript
// In src/selfTest.ts — returns null on success or short failure description
export function selfTest(): string | null { ... }

// In src/index.ts — called on plugin load
const fail = selfTest();
if (fail) {
    showToast("GoofCrypt SELF-TEST FAILED: " + fail);
    vendetta.logger.error("GoofCrypt self-test failed:", fail);
}
```

## Build Step Required

The test suite requires an explicit esbuild step before running. `npm test` handles both steps internally via `scripts/test.mjs`. The harness cannot be run directly with `ts-node` or `tsx` because `stegcloak-rs` imports a `.wasm` file via a bundler-style asset import that plain Node cannot resolve.

```
npm test
  └── scripts/test.mjs
       ├── esbuild: tests/harness.ts → tests/dist/harness.mjs  (bundles .wasm inline)
       └── node --experimental-wasm-stringref tests/dist/harness.mjs
```
